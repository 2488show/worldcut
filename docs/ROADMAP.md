### 下一步：“超越动森”要补的，按价值排序

动森强在**生活感**和**自定义深度**；我们强在**飞出去、真交易、有风险的航线**，这是动森没有的。所以先把动森那一半的差距补到“够用”，再把我们独有的那一半做深。

1. **岛上的生活感**（约 1 周）：小动物（海鸥、螃蟹、蝴蝶，可以抓进图鉴）；家具能用（坐长椅、开路灯）；夜里窗户和路灯亮起来；下雨时岛上也下。
2. **岛主有性格和日程**（约 1–2 周）：每人一种性格、一套话；白天干活、晚上回家；记得你送过什么；偶尔寄信、偶尔坐船来你的岛上逛。
3. **涂装你的飞机和船**（约 1 周）：机身、条纹、帆的颜色和图案；别的玩家路上遇到你、看到你的岛时都能看到。这是我们独有、最能拉开差距的“自定义”。
4. **博物馆**（约 1 周）：捐出鱼、矿石、稀有物，岛上出现展馆；比现在的图鉴更有成就感。
5. **季节与全服活动**（约 2 周）：渔汛、风暴季、海盗猖獗周——所有玩家同一时间遇到，订单和价格跟着变。
6. **室内装修与地形**（2–3 周）：进屋摆家具；铺路、种花、挖池塘。
7. **社交的细节**：送货附一张明信片；岛上的“访客记录”；照相模式。

## 阶段 1.5 · 第二轮时的建议（其中种植、昼夜、海盗的烟幕与雾已在第三轮完成）

按价值排序。前三项是我认为必须先做的。

1. **你来验收声音，然后定方向**（半天到一周）：程序化配乐是否达标？不达标则走 RISKS R11 里的三条路之一。音效同理，逐个听一遍。
2. **真机测试**（2–3 天）：找一台中低端安卓和一台 iPhone，测帧率、触控、发热。若道具渲染掉帧，做“静止道具缓存成贴图”。
3. **首小时节奏调优**（一周）：定一条目标曲线（如：第 8 分钟第一次起飞，第 25 分钟第一次升岛），找 5 个没玩过的人试，按卡点调数值和指引。把钓鱼、潜水、家具做成指引支线。
4. **海盗第二层**：云层躲避（把云暴露给逻辑层）、信号弹 / 烟幕（一次性反制）、护航（花钱雇一架僚机）、海盗巢穴（可以主动去端）。
5. **旅程第二层**：更多天气（雾、雷暴、顺风带）；航线上的随机小岛可降落补给；完全手动落地作为可选的“高手模式”。
6. **家具第二层**：旋转、成套奖励、室内、照相模式（为联网后的“参观”做准备）。
7. **种植与昼夜**：农田（真实时间生长）；昼夜自动循环（月光鱼只在夜里出）。
8. **工程**：`scene.ts` 拆文件补类型；世界改成分块生成（为更大的海域做准备）；存档迁移机制。

## 阶段 2 · 联网 MVP（约 4–6 周）

目标：**两个真实玩家可以互相下单、互相送货、看到对方的岛。** 这就是 MVP。

- 账号：匿名登录起步，之后绑定邮箱或第三方登录
- 岛屿上云：岛屿定义和建筑列表存服务器，访问别人的岛时拉取
- 市场上云：实现 `Backend` 接口的服务器版本。订单、送货单两张表；接单、交货、结算写成数据库事务函数，客户端不能直接改表
- **服务器权威**：金币和库存只在服务器上变动；采集和制造按时间戳校验（防止改本地时间刷资源）
- 海域：每片海 8–12 座岛，新玩家分配到有空位的海域；系统商会订单兜底
- 来访痕迹：谁来过、送了什么
- 埋点：首单完成率、单次游戏时长、每单飞行时长、订单成交时间

**做完的标准**：10 个内测玩家连续一周每天有成交，没有出现刷钱。

## 阶段 3 · 封闭测试与调平衡（约 2–3 周）

- 20–50 人，网页版（发链接即可，更新不需要审核）
- 调经济：物价、订单刷新、金币回收
- 重点观察两个风险：送货会不会腻；市场在这个人数下有没有流动性
- 根据数据决定阶段 5 先做什么

## 迁移到手机端的计划

### 已经为手机做好的

| | 现状 |
|---|---|
| 操作 | 岛上全部是点击；飞行是按住转向加一个加速按钮。已用触摸事件跑通整局 |
| 布局 | 竖屏优先，横屏自适应；面板在窄屏上是底部抽屉；避开刘海和底部横条 |
| 性能 | 画面固定约 11 万像素，与屏幕分辨率无关。桌面无头 Chrome 里 60 fps，Node 里每帧约 3 毫秒 |
| 包体 | 单个 HTML，163 KB（gzip 后 65 KB），没有图片和字体文件 |
| 架构 | 引擎和玩法都不依赖 DOM，只有界面层用了 DOM |
| 存档 | 关页面和切后台时都会保存 |

### 还没验证的（重要）

**没有在真机上跑过。** 上面的性能数字来自桌面环境。阶段 1 结束前应该用 `npm run dev` 在两三台真实手机上各玩一局，这件事不需要等到阶段 4。

### 步骤

1. **PWA**（约 2–3 天）：加 manifest 和离线缓存，能“添加到主屏幕”全屏运行。这一步之后就可以拿给朋友在手机上测。
2. **Capacitor 外壳**（约 1 周）：把同一份网页打包成 iOS 和 Android 应用。当前主版本是 8。
3. **原生能力**（约 1 周）：震动反馈、推送通知（“你的单被接了”“货到了”）、屏幕常亮、返回键、音频后台策略。
4. **触控打磨**（约 1 周）：双指缩放、长按提示、飞行时的拇指区域、不同握持方式。
5. **性能档位**：检测到掉帧时降低像素预算、关闭云影。低端安卓是主要对象。
6. **上架**：商店素材、隐私政策、年龄分级；如果有内购，接商店支付。

### 如果目标是微信小游戏

这是另一条路，成本明显更高：小游戏运行环境没有 DOM，界面必须全部画在画布上，首包限制 4 MB，带内购还需要版号。引擎和玩法代码可以直接复用，**界面层要重写**。是否走这条路取决于目标市场，见风险清单 R2，需要你来决定。
