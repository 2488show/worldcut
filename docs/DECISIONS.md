# 决策记录

你让我自己做取舍并记下来。下面每一条写了：选了什么、为什么、放弃了什么、什么情况下应该推翻。
标 ⚠ 的是我认为你最该看一眼的。

## 一、对原型的判断

**原型是什么**：一个不依赖任何引擎的软件渲染器（约 2100 行 JS），每帧把画面算进一块低分辨率像素缓冲再放大显示。地形是高度图，喷气机是 13 层体素切片，云也是切片。React 只是一层薄壳。没有图片资源。

| | 处理 | 说明 |
|---|---|---|
| 渲染器、调色、云、阴影、尾迹 | **复用** | 画风就在这里 |
| 飞行模型、三种视角的镜头 | **复用** | 手感就在这里；数值原样保留为“游隼” |
| 喷气机模型、座舱、尾焰 | **原样保留** | 三个文件一个字没改 |
| 世界生成 | **重写** | 一整块噪声大陆 → 互不相连的群岛 |
| “喷气机”专用的绘制代码 | **改成通用** | 任何体素模型都能画，飞机、船、小人共用 |
| React 外壳、参数面板、僚机、自动特技 | **去掉** | 换成游戏自己的界面和状态 |

## 二、关键决定

### D1 · 不换引擎，在原型的渲染器上扩展
- **理由**：你要保留的画风和手感，本质上就是这个渲染器和这段飞行代码。换 Godot、Unity、Phaser 意味着两样都要重做一遍再去对齐。它还带来三个实际好处：零美术资源；包体极小；不依赖浏览器，所以整局游戏可以在 Node 里自动跑。
- **代价**：没有现成的编辑器、物理、粒子、动画系统，要什么得自己写。CPU 渲染对像素数敏感（已用固定像素预算解决）。
- **备选**：Godot 重写（工具链好，但画风和手感要重新调）；Phaser/PixiJS（是精灵引擎，不支持这种高度图体素画法）。
- **何时推翻**：如果以后需要大量骨骼动画或 3D 特效。

### D2 · Vite + TypeScript + Preact，界面用 DOM
- **理由**：经营游戏一半的代码是界面，DOM 写面板最快，中文排版、滚动、输入框都是现成的。Preact 只有几 KB。Vite 是 Capacitor 打包的常规搭配。
- **备选**：沿用原型的 React（大 100 多 KB，没有额外好处）；界面全画在画布上（像素风更统一，但工作量是几倍）。
- ⚠ **何时推翻**：如果要上微信小游戏。那里没有 DOM，界面层要重写（见风险 R2）。

### D3 · 世界是“一片环绕的海 + 几座独立的岛”
- **做法**：每座岛是一个柔边圆形遮罩乘以原型的噪声，所以海岸线不规则但岛与岛不会连起来。一片海 2048×2048，四座岛，相距约 10 km（约 1000 像素）。
- **理由**：一人一岛是你的设定；岛的定义只有几个数字，服务器存起来很便宜。
- **备选**：无限流式世界（更大，但现在不需要，而且要改渲染器内层循环）。
- **以后**：跨海域长途航线作为阶段 5 的内容。

### D4 · 建筑和资源点是“印章”，会动的东西是体素切片
- **做法**：建筑、树、矿、跑道、码头都是几行字符画，直接压进地形的高度图；飞机、船、小人用和喷气机相同的切片技术。
- **理由**：同一个渲染器画出来，画风自动统一，光影遮挡都不用另写。加一栋建筑是加几行文本。
- **代价**：每个地面像素只有一个高度和一种材质，建筑做不出悬空结构和窗户这类细节。
- **备选**：给建筑也用体素模型（细节更多，但要处理和地形的遮挡排序，数量多了有开销）。

### D5 · 岛上有一个走路的小人，而不是上帝视角
- **理由**：“类动森”的感觉很大程度来自“我在岛上”。点哪走哪，对手机也自然。
- **代价**：要写寻路（已做，广度优先搜索）；小人会被地形挡住视线。
- **备选**：纯点击建造的经营视角（省事，但像工厂游戏不像生活游戏）。

### D6 ⚠ · 联网方式：异步多人，不做实时同步
- **理由**
  1. 玩法不需要。交易是下单、送货、结算，没有哪一步要求两个人同时在线。
  2. 两个人维护不起实时服务器（房间、同步、掉线重连、作弊）。
  3. 手机网络不稳定。异步意味着飞行全程在本地，只有接单、起飞、降落时联网。
  4. 异步自带一个好处：玩家少的时候，世界不会显得空。
- **代价**：看不到别人实时在飞。
- **备选**：实时联机（Colyseus 之类的房间服务器）；混合（异步为主，后期给同海域玩家加只广播位置的“幽灵”飞机，已列入阶段 5）。
- **何时推翻**：如果测试表明玩家最想要的是“一起飞”，把幽灵飞机提前。

### D7 ⚠ · 后端：先用本地模拟，接口定死；上线用 Supabase
- **切片的做法**：`backend.ts` 里的 `Backend` 接口是客户端与服务器之间的全部约定（查订单、接单、挂单、交货、结算、特产店）。现在由 `LocalBackend` 在浏览器里实现，并扮演其他岛民。联网时只换这一个实现。
- **上线方案**：Supabase（托管 Postgres + 登录 + 行级权限 + 数据库函数）。
  - 订单撮合和货款托管需要事务，订单簿需要关系查询，Postgres 合适。
  - 接单、交货、结算写成数据库函数，客户端没有直接改表的权限。
  - 不需要自己运维服务器。
  - 费用：免费档每月 0 美元，含 500 MB 数据库和 5 万月活，足够内测；但免费项目闲置一周会被暂停，正式运营要升到每月 25 美元起的 Pro 档。
- **备选**：Firebase（文档数据库做订单簿和事务比较别扭）；Cloudflare Workers + D1（更便宜，自己要写的更多）；自建 Node 服务（最灵活，运维负担最大）；Nakama（功能全，对这个规模偏重）。
- ⚠ **何时推翻**：如果主要市场是中国大陆。Supabase 在大陆的可达性我没有验证，届时应换成国内的云开发类服务。接口不变，换的还是那一个文件。

### D8 · 市场规则
- **求购单**由接单者送货；**出售单**由卖家送货。两种单最后都落到“手里有货的人飞过去”，符合你的设定。
- 货款在成交时托管，货到才付。
- 准时有 15% 小费，迟到不罚。这是休闲游戏，只奖不罚。
- 系统商会（NPC）持续挂求购单、买下定价合理的出售单，解决人少时没单可做的问题。

### D9 · 起飞、降落、靠岸是自动的；巡航是手动的；永不坠机
- **理由**：原型本来就撞不上任何东西，这是它手感轻松的原因。手动降落会引入失败、挫败和大量教学，不适合手机上的休闲玩家。
- **做法**：靠近目的地后出现“降落”按钮，按下后飞机沿一条平滑曲线自己进场、滑跑、掉头停好。
- **备选**：手动对准跑道降落（更有飞行感，可以作为以后给高手的可选项，降得好加小费）。

### D10 ⚠ · 对飞行手感做的唯一改动
- **改了什么**：原型里，鼠标 5 秒不动或手指离开屏幕，飞机会自己乱飞并自动翻滚（那是展示模式）。送货时这会把飞机带偏，所以改成：**没有输入时保持直飞**。
- **没改的**：转向缓入、坡度、爬升俯冲、贴地、加速、翻滚、三种视角的镜头，代码和数值都是原样。“游隼”实测巡航 92、加速 166，和原型的 92 × 1.8 一致。
- 如果你想保留展示模式（比如用在标题画面），可以加回来。

### D11 · 触屏操作：按住转向，加速是独立按钮
- **理由**：原型里“按住”等于加速。手指必须按着才能转向，那就等于永远在加速，所以拆开。鼠标操作保持原型的方式（按住加速，点击翻滚）。

### D12 · 竖屏优先，画面固定约 11 万像素
- **理由**：竖屏单手可玩，俯视飞行在竖屏里前方视野更长。固定像素数让手机和桌面的画面与开销一致，并保证每个画面像素是整数个设备像素，不发虚。
- **备选**：锁横屏（追尾和座舱视角更好看，但岛上经营不如竖屏顺手）。现在两种方向都能用，没有锁。

### D13 · 飞机在新手期就能造出来；船是不用金属的便宜选项
- **理由**：你喜欢的是飞行手感，那就不能让玩家等两小时才摸到飞机。目标是 10 分钟内首飞。
- 船的定位是“慢、要绕路、但货舱是飞机的三倍且不用冶炼”。大宗单只有船一趟装得下，两者不互相替代。

### D14 · 原型的喷气机是切片的终点奖励
- 它叫“游隼”，需要铁锭；铁矿石只有石峰岛卖。于是第一条完整的贸易线是：卖木板赚钱 → 飞去石峰岛买铁矿 → 回家炼铁 → 造出原型那架飞机。
- 座舱视角只对游隼开放（那是喷气机的座舱）。

### D15 · 冶炼和再生用真实时间
- 关掉游戏它们也在继续，像动森一样“回来就好了”。
- ⚠ 现在按本机时钟算，改系统时间可以作弊。联网后改由服务器时间戳校验（阶段 2）。

### D16 · 测试方式
- 因为引擎和玩法不依赖浏览器，整局游戏可以在 Node 里用和玩家一样的点击自动打通，还能直接导出截图。这是 D1 带来的。
- 另有 Chrome 里的端到端测试，用真实的鼠标、键盘和触摸事件。

### D17 · 其他小决定
- **游戏名**《云屿航线》是我起的占位名。你的项目叫 Worldcut，如果那才是名字，全局替换即可。
- **界面语言**先只做简体中文，文案集中在数据表和组件里，还没有做多语言框架。
- **打包**成单个 HTML，双击就能玩，也方便发给别人测试。
- **字体**用系统字体，没有引入像素中文字体（完整字库有几 MB）。以后可以做子集。
- **引擎代码**暂时没有加类型（它是原型的无类型代码），新写的玩法和界面是严格类型检查的。

## 二之二、第二轮的决定（D18–D42）

每条：选了什么 · 为什么 · 放弃了什么。

### D18 · 音乐和音效全部程序化合成
**选**：WebAudio 实时合成，零音频文件。音乐是一台生成器（动机 + 变奏 + 留白 + 慢和弦 + 回声/混响），六个场景换调式、速度、配器，在小节线上过渡。
**为什么**：包体不变（整个游戏仍是一个 330 KB 的网页）；没有版权和授权问题；场景间可以真正连续地过渡，而不是两段录音交叉淡入淡出；两个人维护得动。
**放弃**：AI 生成的录音（Suno / Udio 类）——上限更高，但每条 1–3 MB、要处理循环点、授权条款要逐条确认，而且我在这个环境里听不到成品，无法把关。**这是最需要你用耳朵验收的一项**；如果风格不对，`src/ui/audio.ts` 里的 `SCENES` 表是调参入口，换成录音则只需替换 `setScene` 的实现。

### D19 · 游戏层只发“反馈事件”，界面负责播放
**为什么**：游戏逻辑保持无 DOM、无声音，整局可以在 Node 里无头跑；于是“每个操作都有反馈”能写成测试断言。
**放弃**：在逻辑里直接播声音（简单，但不可测）。

### D20 · 反馈分三层，全屏仪式只给真正的里程碑
试跑时 10 分钟出现 4 次全屏仪式，打断感很强，于是熔炉和第一块金属降为横幅。全屏仪式现在只有：第一架飞机、第一艘船、第一次送货、稀有矿、稀有鱼、岛屿升级、炸岛。

### D21 · 采集是多次敲击，命中停顿只用在最后一击
每一击都停顿会让砍一棵树变得拖沓；只在最后一击停 0.09 秒，重量感集中在“倒下”那一刻。

### D22 · 工作台每件 0.8 秒
足够看见锤子落三下，又不至于做 10 块木板变成等待。熔炉仍是真实时间（5–11 秒一炉），可以离开去干别的。

### D23 · 岛上的东西从“地形图章”改成体素道具
**为什么**：图章是高度场，一格一个高度，做不出树冠悬在树干上，放大后只是更大的绿锥。体素道具和战机是同一种画法（切片堆叠），风格天然一致，还能摇、能倒、能挤压。
**代价**：每个道具每帧都要画（约 5 ms / 帧，见 D27）；道具之间靠远近排序，不写深度。
**放弃**：继续用高度场并加高；或引入真 3D 网格（风格会变，包体会涨）。

### D24 · 道具是空心壳，每个体素补画一段侧面
空心让体素数少一半以上。但空心壳在低角度下，上下两片之间会露缝（变成横条纹），所以每个体素除了顶面，再向“下一片”的方向画一小段侧面（暗一档的颜色）。**只对道具启用**，原型战机的画法一个像素没动。

### D25 · 岛上默认倾斜 3D 视角；空格切换；加速让位给 Shift
你说喜欢飞行时“像素又带 3D 的倾斜视角”。岛上的倾斜视角直接复用原型追尾视角的透视投影，只是目标从战机换成小人，所以两种场合是同一个“镜头语言”。空格在岛上和飞行中都是“换视角”（一致比省一个键重要），加速改到 Shift / J；鼠标按住加速不变。正俯视保留，用来摆东西和看全岛。
**放弃**：让镜头自动跟在小人身后转（容易晕，点地走路时方向会乱）。

### D26 · 遮挡物自动半透明
倾斜视角下高的东西会挡住身后的小人。挡住时把它画成半透明（抖动），而不是把镜头抬高——抬高就失去了“有深度”的意义。

### D27 · 性能预算
Node 里：倾斜近景约 9 ms / 帧（道具占 5 ms），正俯视约 5.5 ms。真 Chrome（软件渲染）桌面和手机视口都是 60 帧。视野外和 620 px 以外的道具不画。**真机没测**（风险 R6）。预案：把静止道具按视角缓存成贴图。

### D28 · 工具没有耐久（第六轮推翻，见 D71）
两人团队做不起“修工具”这条支线的平衡，耐久在手机上也是纯负担。材质只决定效率（敲击数 = 硬度 ÷ 材质等级）和能采什么。
**放弃**：《我的世界》式耐久。如果后面需要金属的长期消耗口，优先用载具改装和家具，而不是耐久。

### D29 · 开局不给工具，但前三分钟不卡人
树枝、卵石、纤维徒手捡，足够做石斧和石镐。铜工具要先下矿，铁工具要煤。指引第一步就是“捡东西”。

### D30 · 矿洞和海底“盖在一片空海上”
两个子场景都是把一块地形临时写进世界地图的空海区域，用同一个渲染器画，离开时把海还原。照明（黑暗 + 光圈）和水下染色只是画面最后一道后处理。
**好处**：没有第二套渲染代码。**代价**：同一时间只能有一个子场景；子场景里看不到岛。

### D31 · 矿洞的“发现感”来自“没暴露的矿不显形”
比“满墙都是标好的矿”多一层期待：每挖开一格，周围的岩壁才露出真面目。梯子藏在岩石下而不是放在明处，给了“再挖一格”的理由；细尘提示保证不会真的找不到。硬岩门（第 3、6 层）把“往下”和“升级镐”绑在一起。每 15 分钟重置，防止一次挖空。

### D32 · 钓鱼是“张力对抗”，潜水是“限时 + 瞄准”
两套玩法手感要不同。钓鱼只有一个按键（按住 / 松开），紧张感来自鱼的冲刺；潜水是空间上的——游过去、靠近、射击、看着氧气。失败都不重：断线只是丢这条鱼，缺氧只丢一半渔获。

### D33 · 岛屿生成：瓣状轮廓 + 平原 + 独立山丘；不做侵蚀模拟
你提到可以试侵蚀模拟或真实高程数据。我没有采用：这个画风把高度量化成 2 像素一级的台阶，侵蚀的细节（沟壑、冲积扇）量化后看不出来；整张 2048² 的地图要在手机上 1 秒内生成（现在约 0.5 秒）；真实高程数据要带数据文件进包，还有授权问题。
**实际做法**：随方位起伏的半径（岬角、海湾）+ 噪声毛边 + 内陆压平成沿海平原 + 每岛 1–3 座高斯山丘 + 环礁的潟湖。效果是“看得出平原、山、海湾和沙滩”，成本是几行代码。
**如果以后镜头拉得更近、台阶更细**，再考虑侵蚀。

### D34 · 布局读地形
跑道选最平的低地带（两种朝向都试），村子、机库、码头、矿洞、地标依次按规则落位。换一颗种子，整座岛的摆法都不同。代价是世界生成分两遍（先出高程、再压平要建的地方）。

### D35 · 公平：三项丰度之和恒为 3
随机差异是乐趣，但不能有“欧皇岛”。林 / 矿 / 鱼各 0.75–1.3，和固定。岛只有偏科，没有全面更好。

### D36 · 炸岛：只给新手，最多 3 次
条件是“还没造出第一架载具”。这样它是“选一座喜欢的岛再开始”，而不是可以反复刷的系统。背包保留，避免惩罚犹豫的人。
**放弃**：花金币无限重掷——一定会被用来刷完美岛，而且让“岛是我的”这种感情变淡。

### D37 · 升级是“同一座岛长大”
同种子、半径 200 → 250 → 300。岛的“性格”（轮廓走向、丰度、地标）不变，认得出是自己的岛。门槛是金币 + 送货次数，把升级和核心循环绑在一起。

### D38 · 世界不扩大，旅程靠事件而不是距离变长
世界仍是 2048² 环绕（扩到 4096² 内存和生成时间都是 4 倍，手机吃不消）。邻岛距离拉开到 5.8–11.5 km，一趟 15–30 秒，用风、海鸟、漂流箱、过客、雨云、进场评分和海盗来填。更大的世界留给“分块生成”（路线图）。

### D39 · 降落评的是“进场”，落地仍然自动
完全手动落地和“永不坠机”冲突（落歪了怎么办？）。折中：按下降落那一刻的对正程度决定奖励，之后自动完成。一键降落的可达性保住了，技术好的人有额外收入。

### D40 · 海盗的数值
- 只在 ☠ 航线、3 单之后、有货时出现，概率 0.4 + 0.18 × 危险等级。
- 速度 = 载具基础速度 × 1.45：介于“重载加速”和“轻载加速”之间，所以**载重直接决定能不能硬跑**，这把第 5 项的“载重手感”和第 6 项连了起来。
- 咬住 2.8 秒得手（护板 ×1.5）；抢 30%（货舱锁 15%），一半落海可捞回。
- 放弃条件：拉开 3.3 km、追了 30 秒、或你到了目的岛附近。
- 危险津贴每级 +28%：最远的赤砂岛（☠☠☠）报酬 +84%。
**放弃**：云层躲避（要把云的碰撞暴露给逻辑层，这一轮没做，用“急转弯甩掉”和“雨云减速”代替）；反击和护航（留给下一轮）。

### D41 · 家具的用途是“魅力 → 收入”
纯装饰在没有访客的单机切片里没有回报。给了一个小而明确的数值回报（每 10 魅力 +2% 送货收入，上限 25%），稀有家具因此值得追。联网后，魅力还可以决定你的求购单在别人布告板上的排序。

### D42 · 存档升到 v2，不迁移 v1
世界、物品、岛屿都变了，迁移代码的价值低于它的风险。旧存档被忽略，直接新开。

## 第三轮（2026-11-17）：做成完整的游戏

### D43 · “完整”定义为四件事，并按这个顺序做
有头有尾（标题、主线、结局）→ 能和别人玩 → 补齐简化 → 收尾。**理由**：用户只说了“做成一款完整的游戏”，并且此前要求不要停下来确认。一个没有结局的游戏和一个没有别人的“多人游戏”是最显眼的两个缺口，深度（更多天气之类）排在后面。**备选**：继续按上一轮的建议先调数值和手感——那需要真人试玩数据，我这里拿不到。

### D44 · 联机用页面自带的共享数据库，不自建服务器
**理由**：它现在就能用，不要账号系统、不要部署、不要钱；对“两个人 + 几个朋友”的规模足够。**代价**：它不是裁判，能写的人可以改别人的订单；写权限取决于分享设置（同组织的贡献者及以上）。**备选**：按原计划上 Supabase——对公开运营仍然是对的，路线图里保留。`Backend` 接口没变，将来换实现不动玩法代码。

### D45 · 朋友的岛放进同一个世界，最多两座
**理由**：飞过去是连续的，不用切场景；岛只是种子 + 等级，一张名片就能重建。**代价**：世界只有两块够大的空海域。**备选**：飞出地图边缘后切换到对方的整片海域（数量不限、完全一致，但 `layouts.home` 是“我的岛”这个假设遍布代码，改动面太大）。

### D46 · 让朋友的岛长得和主人看到的一样
地形噪声原来按世界坐标取，同一颗种子换个位置长出来不一样（村子偏了 61 像素）。现在客人的岛从“世界正中”取噪声。**理由**：“去看朋友的岛”如果看到的是另一座岛，就没有意义。原有岛屿的地形不变，旧存档不受影响。

### D47 · 玩家之间只做“求购单”一种
挂单的人押金币，送的人送到收钱。**理由**：一条清楚的回路，状态只有三个。**备选**：玩家也能买走别人的卖单——对称，但多一倍状态，留给以后。

### D48 · 结局是一座看不见的岛，不是一个数值目标
**理由**：音乐的要求是“让人不断想象海的那一边是什么”，结局就应该回答这句话。四片海图残片把好感度、危险航线、终局送货串成一件事。**备选**：以“岛升到最高级”或“攒够多少金币”为终点——没有画面，也没有故事。

### D49 · 好感度按送货单数算，不做送礼和对话树
**理由**：玩家已经在做的事（送货）直接变成关系的进展；两人团队写不起四套对话。每人只有三句话，但每句都只在升级那一刻出现。

### D50 · 烟幕弹是一次性的消耗品，而且要够强
两颗能让满载直飞的飞机保住全部货。**理由**：花钱买的东西如果只能拖几秒，就没人做。它不伤人，符合“紧张但不残酷”。

### D51 · 种下的东西变成普通的资源点
**理由**：不需要第二套“作物”系统；砍、采、再生全部复用。上限 16 棵，防止把岛种满后资源失衡。

### D52 · 存档升到 v3，并迁移 v2
上一轮没迁移是因为世界整个换了；这一轮世界没变，只是多了东西，所以旧存档直接升级。

## 第四轮（2026-11-17）：背包与细节

### D53 · 身上的东西按“格”算，不按重量
8 格快捷栏 + 每个背包一排 8 格，最多 32 格；一格放 30 / 10 / 1 个。**理由**：和动森、我的世界一样，玩家一眼就懂；“格”在手机上能直接画出来。**备选**：按重量——更真实，但要再做一套数字给玩家看。

### D54 · 装不下就不让开始采集，而不是把东西扔在地上
**理由**：扔在地上要做一套“地上的物品”系统（模型、存档、拾取），而且容易丢东西。提前拦住、告诉玩家怎么办，最省心。额外掉落（比如橡果）装不下时送回仓库。**备选**：像动森那样问“要放下哪个”——下一轮可以做。

### D55 · 在家时，工作台、熔炉、装货直接用仓库里的东西
**理由**：格子限制的意义是“出门带什么”，而不是“在家来回搬”。动森在这点上很烦人，我们不学。

### D56 · 奖励和礼物直接进仓库
任务奖励的家具、熔炉在你不在时炼好的锭都进仓库。**理由**：口袋是干活用的，被奖励塞满会打断节奏。

### D57 · 手上的工具是一个单独的小模型，跟着人走
**理由**：不用给小人做“拿斧头”“拿镐”“拿竿”的整套模型变体；抡的动作只是转一个角度。代价：极端视角下工具和手可能对不齐一两个像素。

### D58 · 坐进载具时换成“有人”的模型
**理由**：最简单，也不影响停在机库里的样子（停着的飞机是空的）。

### D59 · 彼岸挪近，避开世界的“对面”
世界首尾相连，离家正好半圈的地方，往东往西一样远，方向会来回跳。所有岛都应该离家不到半圈的 80%。

## 第五轮（2026-11-17）：新手期的生活感

### D60 · 不做玩家互抢；好友偷菜作为恶作剧（你定的）
### D61 · 金币和以物易物都要；岛主那里现在就能以物易物，玩家之间等交易所（你定的）
### D62 · 服务器留到 10 级再上，现在先做新手期（你定的）

### D63 · 岛的等级和岛的大小分开
等级 1–10 是进度，大小只在 4 级和 7 级变。**理由**：每一级都重建一次岛太折腾，玩家也会烦；大多数等级解锁的是玩法。

### D64 · 交易所从 3 级挪到 10 级
上一轮讨论时我提议 3 级开交易所。你决定服务器留到 10 级，所以 3 级改成宠物、交易所放到 10 级。

### D65 · 小动物：不动就不会吓跑
走着靠近才可能吓跑，站定挥网一定能捉到（只要它还在网的范围里）。**理由**：动森的“慢慢走”在点击操作和手机上很难做到；“停下来、挥网”是点一下就能完成的节奏。

### D66 · 菜地自动排在村子旁边，不让玩家摆
**理由**：新手期先有地种；自由摆放菜地放到以后的“铺路、改地形”里一起做。

### D67 · 作物不用浇水，下雨长得快
**理由**：浇水是每天的重复劳动，对手机玩家是负担；下雨加速给天气一个实际的意义。

### D68 · 驯服是“喂三次”，不是小游戏
**理由**：新手期要简单；难度放在“找到对的颜色”和“备好它爱吃的、往往是别的岛的东西”上，这正好连着交易和航线。

### D69 · 野生动物每天换一批
**理由**：想要某种颜色就得反复去找，“今天石峰岛有没有黑羊”成为出门的理由。

### D70 · 一只宠物跟着你，连坐飞机也跟着
**理由**：宠物要被看见才有意义；跟着去别的岛，别人联机时也能看到（联机显示下一步做）。

### D71 · 所有工具都会坏（推翻 D28）
用户要求“都会”：石、铜、铁、钓竿、网、鱼枪都会坏。次数按材质拉开（40 / 120 / 300），让升级工具的意义从“快”变成“快而且耐用”；修理便宜（一份同材质的料），所以坏掉是提醒而不是惩罚。快坏时只提醒一次，坏了有碎屑和提示。
**取舍**：手机上耐久仍是负担，所以不做锋利度、不做部分修理，修就是修满。

### D72 · 载具十级、四代；同一代原地改装，跨代要重造
第一代 1–3 级，第二代 4–6，第三代 7–9，第四代 10。改装保留涂装和身份，重造意味着新的模型、新的涂装——这是用户说的“卖点和损耗点”：材料和颜料周期性地被消耗，高等级玩家有东西可做、可卖。
本轮做了第一代全部、第二代的 4 级、第三代 7 级（原型游隼）；其余在数据里标“规划中”，界面上看得到阶梯但造不了。

### D73 · 第一架必须亲手造；整架买卖留到 10 级的市场
用户：新手的第一架飞机要亲手造；后期市场面向会设计的高等级玩家，卖设计和巧思。所以现在没有“买载具”，只有“拆掉”（拆回第一级材料的一半），避免多余的旧载具堆着没出路。

### D74 · 损耗分三项：引擎、机身、涂装
引擎按航程（可预期，定期保养），机身按事件（被抢、被追、暴雨、硬着陆——战斗回来要大修），涂装按趟数和天气（看得见的褪色）。只有低于 60% 才开始影响速度和货舱，免得刚飞两趟就被逼去修。外岛只收金币且贵一倍：鼓励回家修，也给金币一个去处。

### D75 · 涂装用 8 种颜料、12×8 图案，每辆载具生成自己的模型
颜色固定为 8 种（就是 8 种颜料），保证像素风格统一、存档小（一个涂装约 150 字节）、联机好检查。模型在颜色槽里按语义分区（机身、点缀、帆布、图案），换涂装只是重填颜色、重画图案，不用改模型。原型的喷气机不能涂（它的配色是原型的一部分）。

### D76 · 涂装编辑器先不限制
用户：一个月后上线，先不管。图案编辑器不做审核和举报；联机只传颜色和 12×8 的格子，读入时逐项清洗。上线前要补举报入口（见 RISKS R28）。

### D77 · 联机时你的载具会出现在别人的航线上
岛卡里带上最得意的那辆（有涂装的优先、其次等级最高）。路上的过客七成换成真玩家的载具和岛名——涂装第一次有了“被看见”的地方。

### D78 · 一个月后上线
用户计划约一个月后上线。之后的顺序：博物馆 → 季节与全服活动（渔汛、风暴季，按真实日期算）→ 室内装修与地形。服务器、交易所在 10 级。

### D79 · 摆放的颜色：绿 = 能放，红 = 不能
用户说“能放显示红色，不能放显示蓝色”。我用了几乎所有游戏的惯例（绿能 / 红不能），因为玩家不用学；颜色在 `aimAt` 里一行，用户坚持就改。

### D80 · 所有东西用一种摆放：半透明预览 + 原因
家具、树种、熔炉、屋里的家具都走 `startDecor → aimAt → placeHere`。不能放时直接说为什么（多数是“地不平”），并指向铲子。鼠标点一下就放；手机点两下（第一下看，第二下放），避免误放。

### D81 · 铲子只铲平、不挖坑
“造空地”最常见的障碍是地面不平（`canPlace` 要求完全平）。铲子把 11×11 铲到中位高度，顺手收走小东西；树和石头仍要斧和镐。挖池塘、堆山留到“改地形”那一轮。铲平记在存档，岛升级后重放。

### D82 · 室内像矿洞一样搭在空海上
同一个渲染器、同一套走路和点选，不另写一个 2D 场景；前墙只做窗台，斜视角能看进去；身后一道深色高坡挡住海。代价：屋子是固定的五个房间，暂时不能扩建。

### D83 · 五个房间按真实的家来
卧室、卫生间（马桶、洗手台、淋浴）、厨房、客厅、半隔开的会客区。用户提到的“客厅、会客室、厕所、淋浴”都在；会客区留给以后“岛民来做客”。

### D84 · 体力和饱腹，照星露谷的节奏但更宽松
体力 100，常用动作 1–4 点；只有不够时才拦（不像星露谷到负数会晕倒）。饿只让干活更费力，不直接扣血——用户说先不要血条。做熟的食物是体力的主要来源，让灶台和菜地、渔获连起来。

### D85 · 一天的结束：床、两点累倒、小结
18 点后能睡；凌晨 2 点累倒扣 5%（最多 200）金币，只回六成。在外岛累倒就借住，不把人瞬移回家（载具还停在外岛）。睡觉时的小结给“一天”一个收尾，这是动森没有、星露谷让人上瘾的地方。

### D86 · 天气按天固定，电视预报
每个岛每天“多雨 / 晴”由种子和日期算出，人人一样；电视能看明天。让“明天干什么”有了计划的依据（下雨种地钓鱼，晴天出海）。

### D87 · 温馨度
家具魅力 + 每间屋配齐的奖励。现在只是显示，下一步给奖励（像动森的 HHA 评分）。

### D88 · 矿洞：路永远挖开，矿另外长
原来整层重置是为了让矿“取之不尽”，代价是辛苦挖的路没了。现在把“路”和“矿”拆开：挖开的格子永久保存，矿脉每 2 个游戏日在岩壁里重新长出（另一个随机数种子）。玩家的劳动留得住，资源也不会枯竭。

### D89 · 光线用关键帧插值，不用公式
一天 9 个手调的关键时刻 + smoothstep 插值，而不是用太阳角度算。原因：像素画的配色要“好看”而不是“物理正确”（黄昏要偏粉、深夜要偏蓝紫），关键帧让美术能直接改颜色；插值保证不跳。调色板按变化量重算，不是每帧算，手机上不费电。

### D90 · 天气五种，按天固定、按阵起落
继续 D86 的“按天固定、人人一样”（联机时大家看到同一场雨），但一天里分几阵慢慢起落。比例偏向晴天；雪不按季节（季节还没做，做了以后雪只在冬天）。

### D91 · 下雨天躺在床上：一扇窗，三层声音
这是“温馨”最直接的一刻，所以单独做一个画面：屋里镜头不够看到窗外，就把窗画成一张会动的画（160×108 像素，同一个画风）。声音分窗外（雨 / 雪）、屋里（壁炉）、音乐三层，各自淡入淡出。它不给任何奖励之外的东西（只是慢慢回体力）——就是让人愿意停下来。

### D92 · 人用部件拼，不再手画整块
手画的人物模型改一个发型就要重画五个姿势。部件拼装后，捏人的每个选项自动适用于所有姿势、所有载具上的骑手、所有岛主；联机时别人的样子也只要存一份很小的 Look。画风不变（同一个渲染器），比例缩到 0.76，让人和房子、树的比例更像动森。

### D93 · 横版潜水是一个独立的小画面
不在 3D 体素场景里潜水，而是一个 320×180 的侧面像素画面（Canvas 2D）。理由：横版才看得出“深度”这件事（越往下越暗、越危险），操作也简单（点哪儿射哪儿），也是你给的参考图的样子。代价是两套画法；鱼、珊瑚都是程序画的，不需要美术资源。

### D94 · 每片海不同的鱼，按岛的地形分
鱼的出现按“哪片海 × 多深 × 白天 / 夜里”加权。让“去别的岛潜水”有理由，也和航线、送货连起来（顺路潜一下）。

### D95 · 请客吃饭：好感和魅力，一天最多一位客人
来客每天最多一位，避免刷魅力；招待分加到魅力里但封顶 80，不压过家具和建筑。过场对话按菜、天气、对方的岛拼出来，“动森腔”是逐字合成的音节（不需要录音）。联机时，别的玩家给你送货就会派一个人来——这是“被看见”的反馈。

### D96 · 熟练度按“活”分五种，只省体力加小好处
不做星露谷那种技能选择分支（两个人一个月做不完平衡）。每级固定省 5% 体力 + 一项小加成，5/10 级各一个具体的“本事”。目的是让体力从“干不动”变成“越干越省力”，而不是把玩家拉开差距；数值都在一张表里。

### D97 · 信箱是所有“异步消息”的统一出口
感谢、回信、评定、联机留言都是一封信，同一个面板、同一个提醒（小红旗 + 数字）。以后偷菜纸条、好友礼物、活动通知都不需要新界面。信只在早上来（排队的信等到第二天），让“早上出门先看信”成为每天的仪式。

### D98 · 做客打分用温馨度，不另做一套评分
来客的星级和每周评定用同一个温馨度公式和同一套门槛（70/95/115/140）。初始家具正好 3 星，添 7 件常见家具到 4 星——让第一次升星触手可及，5 星要用心摆。

### D99 · 每周评定从第 8 天开始，一周一次
太频繁会变成刷奖品。奖品是家具和金币，不给魅力（魅力只来自“别人看到”：来客、请客、家具摆在岛上），避免同一件事被算两次。

### D100 · 炒股：虚构公司、金币、跟游戏里的事挂钩
不接任何真实行情，只做五家岛屿公司；股价 = 向“价值”回归 + 每小时噪声，价值由天气、季节、公司新闻和玩家送货推动。这样炒股不是纯运气：会看天气预报、知道自己要往哪送货的人有优势，也把送货和股市连起来了。1% 手续费防止秒买秒卖。随机数按岛的种子和小时算，同一座岛结果固定，联机也一致。

### D101 · 照片存在设备上，不进存档
一张原图 50–150 KB，进存档就会每次同步到云端。相册放本机（最多 12 张），只把约 10 KB 的缩略图作为明信片随订单发给另一个玩家，并严格检查格式和大小。

### D102 · 染色用涂装的颜料，基本色免费
衣服和飞机共用 8 种颜料，让颜料多一个用处；基本色免费，保证不想花资源的玩家也能换衣服。

### D103 · 季节 7 天一季、按游戏日
一年 28 个游戏日（约 9 小时游戏时间），一个月内能看到完整的一年。颜色用调色板的颜色映射做，不需要另做一套秋冬模型；变色在每季前两天过渡。

### D104 · 钓鱼采用"方向对抗"，潜水保留横版
调研了动森、星露谷、Dredge、盗贼之海和潜水员戴夫，详见 FISHING-DIVING.md。搏鱼采用盗贼之海的做法：鱼往哪边冲，就往反方向拉；鱼跳的时候松手；鱼歇着的时候收线。没有用星露谷的竖条，原因有三：
- 这种做法有"和鱼较劲"的身体感。
- 手机上用一块拉线板就能玩，不需要精确的手指。
- 输了不疼：竿不会坏，没有惩罚。

潜水不改成第一人称，因为手机上会晕，也和像素风格不一致。改为往戴夫的方向加深：深度带、补气的气泡柱、宝箱，越深越稀有。

### D105 · 拿起的家具留在原地，而不是收回背包
上一轮东西"消失"的根源是：拿起就进背包，玩家看不到它去了哪里。现在拿起只是"抬起来"：
- 取消就放回原处。
- 收起来时先放背包，满了进家具箱（屋里的家具箱）。
- 放下后有 12 秒可以撤回。

任何路径都不允许凭空少一件，用一个"物品总数守恒"的测试锁死。

### D106 · 自动对齐用"候选位置打分"，不做网格
候选位置包括：靠墙、居中、对齐、对称、围着桌子、地毯垫底、床头柜、墙角。每个候选的得分 = 离手指的距离 − 规则加分，最后选合法且得分最好的那个。比网格自然，也比纯自由省心。自由模式和逐格微调一直保留，给想精确摆放的人。

### D107 · 家具分四层：地上、地毯、墙上、桌上
每件家具声明自己放在哪一层，以及桌面高度。叠放只做"小东西放在桌面上"和"坐垫放在地毯上"，不做任意堆叠：任意堆叠的碰撞和存档复杂度都高，而玩家想要的叠放其实就这几种。

### D108 · 窗外的景色直接画进窗户模型的调色板
每块玻璃的每一格都有自己的调色板编号，每帧按时间和天气重新填色。不用另一张画布，也不用多一次渲染，开销几乎为零。窗外还会跟着屋外真实的天气变。

### D109 · 睡觉的镜头由"距离系数"驱动
镜头的仰角和距离都缓动到目标：低机位（19°），从枕边看向前方最近的窗。用"近"系数拉近距离，避免镜头钻进墙里。屋子没有天花板，所以只选睡的人前方的窗，不往身后看。

### D110 · UI 用"纸"和"书"统一，而不是做一套新组件
- 所有面板换上同一套纸色、楷体标题和胶带。
- 内容多的两个面板（日志、岛务）做成可以翻的书。
- 其他面板只换皮，并删字。

这样一次换掉整个游戏的气质，不用重写 30 多个面板。

### D111 · 放着不动 8 秒，界面就退场
手机屏幕小，放松的时候不该看到一排按钮。淡出而不是隐藏，一碰屏幕就回来。下一步的便签永远留着，满足"引导必须一直在"的要求。

### D112 · 房子做成岛上真实的建筑，而不是另一个场景
第十一轮的屋子是单独搭在海上的场景，靠一圈黑墙遮住周围，镜头、窗户、进出门都要另写一套，bug 也多。用户建议改成一体化，我同意。
现在墙和地板压进岛的地形，屋顶是一个模型；进门时只掀掉屋顶、把前墙降成矮栏，并切换镜头。家具一直在岛上，只是在屋外时藏起来，免得从屋顶穿出来。

### D113 · 缩房间，不缩家具
测了模型：小人 9×7×18（画的时候再缩到 0.76），床 13×19，沙发 19×9，比例本来就对。屋子显得空，是因为原来有 150×104。所以室内缩到 89×63，家具保持原大小。这样既紧凑，又不会出现"缩了以后看不清"的问题。

### D114 · 屋里的镜头锁住朝向
前墙降成矮栏，只有从那一侧看进去才不挡视线。在屋里转镜头会被墙挡住，所以进屋时把镜头转到正对门的方向，出门再还原。

### D115 · 钓竿回到第十轮的玩法
用户试玩后更喜欢第十轮的手感，按用户的意思回退。尺寸纪录和图鉴不加操作负担，所以保留。

### D116 · 电脑做成"桌面"，把零散的面板收进去
用户选的方案。电脑成了家里的信息中心：股市、信箱、天气、图鉴、相册都在上面，玩家会想每天坐下来看一眼。
原来的面板没有重写。它们本来都放在一个纸质外框里，进电脑窗口时就不显示这个外框，只显示内容。这样同一份界面，在屋里是纸，在电脑上是窗口。

### D117 · 扫雷每天只有前 3 局给钱
扫雷是用来打发时间的，不能比干活还划算。每天前 3 局胜利给 15 / 40 / 90 金币（初级 / 中级 / 高级），之后只记成绩。

### D118 · 鱼饵只改变"来的是什么鱼"，不改变钓的手感
用户刚把搏鱼回退到第十轮，说明他喜欢现在的手感。所以鱼饵只调整各种鱼被选中的权重和等待时间，提竿和收线完全不变。
活饵在鱼咬钩时被吃掉，拟饵不会消耗。饵的来源都接在已有的玩法上：铲子挖蚯蚓和小虾，工作台做面团饵、鱿鱼块和拟饵。

### D119 · 少写字：鱼饵招什么鱼用图标表示
参考图的说明框里写着鱼名。我们改成一排鱼的小图标：钓到过的显示彩色，没钓到过的只是剪影。字更少，也给玩家留了一点去试的好奇心。

### D120 · 窗户做成墙上的开口，不再画风景
房子已经在岛上，窗外就是真的岛。墙在窗口处只砌到窗台，窗框和过梁是一个模型。画上去的风景删掉。屋里时雨雪按"像素对应的地面是否在房子范围内"来遮掉，室内的家具另外打标记。

### D121 · 床边机位：右手侧、低、近，墙头贴着画面顶
按用户给的参考图。房子没有天花板，所以让远处墙头正好在画面顶端，这样不会露出墙上方的天。镜头和床之间的内墙在躺下时暂时放平。近景下体素很大，这是接受的代价。

### D122 · 屋里镜头的朝向单独算
镜头和家具的角度约定正负号相反，不能共用同一个值。四个朝向都有测试。

### D123 · 屋里和屋外分开：外面小，里面大
用户要多层楼，也要屋里比屋外大。房子和岛做成一体时，这两样都做不到：屋里屋外是同一块地，大小必然一样；地形是一层高度图，楼上楼下没法叠在一起。
所以回到"进门换到另一个地方"，但不像第十一轮那样浮在黑色里：每层楼放在远离所有岛的一片海上，有一圈小院子，窗外是真的天、真的天气和海。代价是窗外不再是自己岛上的那棵树。用户确认了这个取舍。

### D124 · 房子按四档长大，跟着岛的等级
小木屋（开局）→ 砖瓦房（岛 2 级）→ 两层（3 级）→ 三层（4 级）。每档花金币和材料，在岛务手账里扩建。档位和岛的等级挂钩，这样"岛变大"和"家变大"是同一条线，不会出现大岛上一间小屋、或小岛上一栋楼。
旧存档直接算砖瓦房（它们已经有五个房间），不用重新摆家具。

### D125 · 扩建时家具怎么搬
原则还是"什么都不丢"。小木屋 → 砖瓦房：砖瓦房里有位置的家具放到位置上，砖瓦房缺的家具配齐；放不下的进家具箱，而不是随便找个空地，因为乱放比收起来更难看。
砖瓦房 → 两层：还在原位的卧室家具一起搬上二楼，原卧室改书房，楼梯放在那里。玩家挪动过的家具不动，玩家可以自己搬上楼。

### D126 · 拿着家具可以上下楼
多层楼最常见的需求是"把这个搬到楼上去"。拿起的家具本来就一直留在存档里（第十一轮的做法），所以只要换楼层时不取消拿起，放下时记下当前楼层就行。

### D127 · 每天一个小心愿，回礼是做不出来的家具
给每天上线一个小理由。要的东西都很容易拿到，当天有效，错过不罚。回礼是工作台做不出的小家具，这样它不会和做家具重复，也让家里慢慢多出"别人送的东西"。

### D128 · 合影和留言本是"做客"的结尾
异步联机现在只有送货，缺人情味。做客时已经有一段对话，在最后加一句合影、一行留言，几乎不增加操作，却让家里留下痕迹：相册里多一张照片，可以挂墙上；留言本里多一句话。
本轮先接在每天来的岛主身上；联机玩家来访写留言本留到联机真实环境验证之后。

### D129 · 只在床边镜头用精细模型
整屋换成半大小体素会让普通视角显得太碎，而且画得慢。所以只在躺下时把床边几件换成精细版，起来换回去。

## 第十七轮（2026-11-18）：订单板与十级载具
### D130 订单板会过期、会照着货舱出单
没人接的单 8 分钟后撤下；新单件数不超过玩家最大货舱，货舱越大单子越大（最多 6 倍）；板上没有能接的安全单时，下一张必是安全岛的。装不下的单不让接。原因：试玩机器人 3 单后板上全是接不了的单，24 分钟一动不动。

### D131 岛的等级是主轴，各系统 10 级
见 docs/LEVELS-10.md。每级至少一个看得见的变化加一个新的可做的事；3–6 级数值差距小，靠外观和用法区分。满级目标约 30 小时，之后交给后续的经济、大亨、陆战海战等内容。

### D132 删掉游隼，9 级给大型货机
用户决定。第三代飞机改成"银翼"一线（7 银翼、8 银翼货机、9 大型货机）。存档里的 id 仍叫 falcon，旧存档里的游隼变成银翼。

### D133 飞艇是运输艇
用户的设想：开始世界副本后的第一艘大型运输艇，能装小飞机、重要资源和大宗货，将来卖飞机时用它送过去。本轮先做：货舱最大（80），起飞时自动把停在同一处的一架飞机挂进吊舱，一起到达。卖飞机、装重要资源等留到市场做好以后。

### D134 房子后六档是"侧翼"，不是往上一直加楼
新房间各占海上一块（和一到三楼一样），用侧墙上的门或楼梯连过去：工坊、温室从一楼开门，水族馆在工坊楼下，观星塔和灯室在阁楼上面，露台在温室旁边。原因：九层直上的楼又难走又难看；侧门让一楼当"中心"，走两步就到。外观上主楼不动，左右加温室和工坊，后角起塔，最后变灯塔。每档带一件有用的家具（家用工作台、花盆架、鱼缸、望远镜、泳池、灯塔灯）。

### D135 岛 6–10 级各开一座建筑，先做单机版
牧场（繁殖）、小店（挂卖）、货运站（雇人）、灯塔（过路费 + 转运单）、交易所（浮动价格）。都由工作台做的套件放下，和熔炉、餐厅一样；岛扩地时收回成套件。原因：每一级都要有一个新玩法而不只是数字；原先这几级要等联机服务器，先用 NPC 做出来，联机后小店和交易所换成真人。雇人只走危险度 1 以内的航线、拿两成，所以自己飞仍然更赚。

### D136 全游戏的界面统一成电脑窗口（云屿 95）
用户说界面太割裂（电脑里的信箱是手写纸，岛上是纸本手账），选了"全部改成电脑风格"。所有面板都是同一种窗口：灰色斜面边框、蓝色标题栏、白色内容区、斜面按钮；日志和岛务手账变成带页签的窗口；HUD 的任务和提示是黄色提示框。实现是 styles.css 末尾一整块主题覆盖，加 Sheet、Book 两个组件的标题栏。钓具箱、电脑桌面、床边窗这几个本身就是"东西"的画面保留原样。

### D137 像素字体
用户觉得字体和像素画风不搭。用 Fusion Pixel 12px 简体（SIL OFL 1.1，npm 的 @fontsource 包），裁成游戏里用到的字加 GB2312 一级字（3954 字，117 KB），内嵌进单文件。字号尽量用 12 的整数倍保证清晰；像素字没有粗体，粗细改用颜色和分隔线表示。

### D138 收件箱是一个邮件程序；心愿可以当面交、留三天
信箱门口和电脑里打开的是同一个"云屿邮局"：左边信件列表、右边正文和附件，手机上一次一栏。心愿以前只能点心形按钮寄、当天作废，用户飞过去当面交被拒；现在也能当面交，三天内有效。

### D139 屋里的家具也算岛的魅力（四分之一）
用户卡在 4 级“魅力 20”：魅力原来只算岛上户外摆的家具和请客分，屋里布置得再好也是 0，升级条件也没说怎么加。现在屋里家具魅力的四分之一计入（砖瓦房开局约 +15），条件文字写明三种来源，岛务手账里显示分项。

### D140 视角控制放进设置，手机用两指手势
用户要求画面上不放视角按钮。网页在设置窗口里调；手机两指捏合 = 远近，两指拧 = 转镜头。键盘快捷键保留。

### D141 菜地：一整片地，荒地 → 耕地 → 好地 → 肥地
用户定的：初始都叫荒地，靠播种、浇水、施肥变好；不浇水当天不长。我的取舍：浇水一次一整排（24 块地不会变成苦工）；下雨算浇水；肥料来自堆肥箱（把多余的东西变成肥料，给杂草和小鱼一个去处）；离线生长取消。参考了星露谷的浇水 / 肥料和动森的成片田地。

### D142 船钓、鱼筐、晒鱼架
抛锚才能钓（船不停就甩不了竿），抛锚时风和海流不推船。远海（离每座岛的边都超过 330）大鱼权重翻倍以上。鱼筐不占背包，记每条鱼的长度。晒鱼架改成便宜的早期家具，牌子展示最大的一条——用户说"让玩家能炫耀大鱼非常重要"。

### D143 坐着吃饱腹多一成；小动作不拦人
让摆餐桌、去餐厅有实际好处，而不只是好看。所有小动作都可以走开打断，效果在开始时或打断时结算，不会丢东西。电脑桌面保持全屏，只在前后加坐下、开机和关机。

### D144 餐厅和灶台分"用餐 / 后厨"两页
之前餐厅窗口只有后厨，看起来只能做饭。现成的菜放在"用餐"页，做完一道可以"现在吃"。

## D162 · 微信版没声音：把微信的 WebAudio 补齐（2026-11-20）
- **现象**：用户反馈微信版没声音。
- **原因（推测）**：微信的 WebAudio 还是 beta，和浏览器的不一样。
  - 我们的引擎会写 `a.connect(b).connect(c)` 这样的链式连接；微信的 `connect()` 可能不返回目标节点。
  - AudioParam 可能缺 `setTargetAtTime` 等调度方法。
  - 没有卷积混响。
  - 第一次报错后，保护层就把声音整个关掉了。
- **修法**：
  - shim 在每个节点出厂时补齐：`connect` 改成返回目标节点；缺的 AudioParam 方法用线性渐变代替；建好后马上 `resume()`。
  - `wx.setInnerAudioOption({ obeyMuteSwitch: false })`，让手机静音键不压掉游戏声音。
  - audio.ts 不再写死 `window.` 和 `localStorage`，改为从全局对象取。
- **排查入口**：设置里加了"声音状态"一行（正常 / 被暂停 / 出错 + 错误原文），还有"试听""重启声音"两个按钮。
- **验证**：测试页加了 `?wxaudio` 模式，模拟一个残缺的微信 WebAudio（不能链式连接、没有 setTargetAtTime、没有压缩器和卷积器），引擎照样出声。真机还没验证。
